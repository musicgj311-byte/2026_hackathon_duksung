## 1. 프로젝트 목적

스미싱은 해마다 늘고 있습니다. KISA가 2024년 한 해 동안 탐지한 스미싱 문자만 약 219만 건입니다.
기존 서비스는 대부분 **사용자가 먼저 의심하고 직접 확인해야** 작동합니다. 의심 문자를 복사해 붙여 넣거나 신고 창구를 찾아가는 방식입니다.
그래서 판단이 어려운 사람일수록 보호에서 빠집니다.

| 대상 | 기존 경고가 닿지 않는 이유 |
| --- | --- |
| 어르신 | 작은 글씨와 어려운 보안 용어 |
| 시각장애인 | 화면 경고를 볼 수 없음 |
| 청각장애인 | 소리 알림을 들을 수 없음 |
| 발달장애인 | 긴 설명을 이해하기 어려움 |
| 외국인 주민 | 한국어 경고를 읽기 어려움 |

**모두안심**은 사용자가 의심하거나 판단하지 않아도 작동하는 구조를 목표로 합니다.

- **감지**: 문자·카카오톡이 오는 순간 기기와 서버가 자동으로 판정합니다.
- **쉬운 경고**: 사용자 특성에 맞춰 큰 글씨·음성·화면·모국어로 경고합니다.
- **가족 연결**: 위험할 때 보호자에게 바로 알립니다.

판정은 하나지만, 전달은 사람마다 다릅니다.

## 2. 기술 구성

| 구분 | 사용 기술 |
| --- | --- |
| 서버 | FastAPI (Python) |
| URL 검사 | 단축 URL 해제 · Google Safe Browsing · VirusTotal · 자체 차단 목록 |
| LLM 판단 | Google Gemini |
| 데이터베이스 | SQLite · SQLModel |
| 푸시 알림 | Firebase Cloud Messaging (FCM) |
| 앱 | Android |
| 배포 및 운영 | Railway |
| 데이터 저장소 | Railway Volume |
| 설정 및 실행 | 환경변수(.env) · uv |

### 판정 흐름

```
문자·카톡 수신 (알림 읽기)
   │
① 기기 내부 1차 판정 ── 저장된 연락처 + 링크·위험 단어 없음 → 통과 (서버로 보내지 않음)
   │
② 서버 · 빠른 신호 ── 단축 URL 해제 → Safe Browsing · VirusTotal · 차단 목록 · 도메인 생성일
   │                    └ 악성 목록에 있으면 즉시 '위험' 확정
③ LLM 판단 ── 애매한 문자만 Gemini가 문장의 의도를 판단 (5초 초과 시 '주의')
   │
④ 최종 판정 ── 위험 / 주의 / 안전해 보임
   │
⑤ 전달 ── 사용자: 맞춤 경고 · 보호자: 위험일 때만 판정 결과 전송 (문자 원문 제외)
```

## 3. 구현 기능

### 판정 서버
- 기기 → 서버 → LLM으로 이어지는 단계별 판정
- 링크 없이 문자 속 번호로 전화를 유도하는 수법 감지 (카드 발급·해외결제 사칭 등)
- 글자를 깨뜨려 키워드를 피하는 문자(예: "자,,금")는 LLM이 의도로 판단
- 저장된 연락처라도 송금을 요구하면 계정 도용 가능성이 있어 최대 '주의'로 안내
- '안전'이라고 단정하지 않고, 문제가 없어 보이면 표시 없이 확인 카드만 닫음

### 사용자 맞춤 경고 (Android)
- 처음 설정: 역할(보호 대상자·보호자) → 알림 방식 → 언어 → 필수 권한
- 알림 방식
  - 큰 글씨와 소리 (어르신 기본)
  - 화면과 진동 (청각장애인)
  - 단순한 안내 (발달장애인)
  - 소리 중심 (시각장애인)
- 다국어 경고: 한국어 · English · Tiếng Việt · 中文
- 다른 앱 사용 중에는 그 앱 위에 경고, 화면 잠금 상태에서는 잠금화면 알림 후 전체 경고
- 링크가 있는 문자는 판정 전에 "확인 중, 누르지 마세요"를 먼저 표시
- 가족에게 전화하기: 보호자 번호가 입력된 기본 전화 앱을 열어 줌 (전화 권한 불필요)

### 보호자 연결
- 6자리 일회용 연결 코드 발급 (발급 후 10분 유효)
- 보호자가 코드를 입력하면 보호 대상자와 연결
- 연결 해제 API

### 보호자 알림
- 위험 판정일 때만 FCM 푸시 알림 발송
- 개인정보 보호를 위해 문자 원문 대신 판정 결과만 전송
- 알림 전송 결과를 DB에 기록, FCM 토큰이 없으면 `no_token` 상태로 기록

### 데이터 관리
- SQLModel로 데이터 모델 설계, SQLite에 저장
- 기기 ID로 사용자 식별, 역할·언어·알림 설정 저장 및 수정
- 보호자와 보호 대상자 간 연결 정보 관리
- 자체 악성 도메인 차단 목록
- Railway 영구 저장 볼륨에 보관해 재배포 후에도 데이터 유지

### 성능 검증
| 항목 | 결과 |
| --- | --- |
| 개발용 테스트셋 (98개, 사기 18 · 정상 80) | 사기 18/18 경고, 정상 78/80 통과, 정상을 '위험'으로 오판 0 |
| 홀드아웃 (처음 보는 문자 27개) | 허용 범위 안 24/27 (89%) → 규칙 보완 후 재채점 26/27 (96%) |
| 놓친 사기 | 0 (개선 전후 모두) |

## 4. 실행 방법


### 서버 (FastAPI)

**1) 저장소 받기**
```bash
git clone https://github.com/<organization>/<repository>.git
cd <repository>/<server-folder>
```

**2) 의존성 설치** ([uv](https://docs.astral.sh/uv/) 필요)
```bash
uv sync
```

**3) 환경변수 설정**

`.env.example`을 복사해 `.env`를 만들고 키를 채워 넣습니다.
```bash
cp .env.example .env
```
```env
GEMINI_API_KEY=<Gemini API 키>
SAFE_BROWSING_API_KEY=<Google Safe Browsing API 키>
VIRUSTOTAL_API_KEY=<VirusTotal API 키>
FIREBASE_CREDENTIALS=<Firebase 서비스 계정 JSON 경로>
DATABASE_URL=sqlite:///./data/app.db
```


**4) 서버 실행**
```bash
uv run uvicorn <app.main>:app --reload
```
실행 후 `http://localhost:8000/docs`에서 API 문서를 확인할 수 있습니다.

### Android 앱

1. Android Studio에서 `<android-folder>` 폴더를 엽니다.
2. Firebase 콘솔에서 받은 `google-services.json`을 `app/` 폴더에 넣습니다.
3. 서버 주소를 설정합니다. (로컬: `http://10.0.2.2:8000`, 배포: Railway 주소)
4. 기기 또는 에뮬레이터에서 실행합니다.
5. 처음 실행 시 **알림 읽기 · 다른 앱 위에 표시 · 경고 알림 표시** 권한을 허용합니다.

### 배포 (Railway)

1. Railway에서 새 프로젝트를 만들고 GitHub 레포를 연결합니다.
2. Variables에 `.env`와 같은 환경변수를 등록합니다.
3. Volume을 추가하고 SQLite 파일 경로(예: `/app/data`)에 마운트합니다.
4. 배포가 끝나면 발급된 HTTPS 주소를 앱의 서버 주소로 설정합니다.
